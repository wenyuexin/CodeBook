# MongoDB 


## 一、基础概念

### 1. 什么是 MongoDB？它与传统关系型数据库（如MySQL）的核心区别是什么？

**参考答案：**

MongoDB 是一个基于分布式文件存储的、面向文档的 NoSQL 数据库，由 C++ 编写，旨在为 Web 应用提供可扩展的高性能数据存储解决方案。

MongoDB 与 MySQL 的核心区别如下：

| 维度 | MySQL（关系型） | MongoDB（文档型） |
|------|----------------|------------------|
| 数据模型 | 表 + 行 + 列，需预定义 Schema | 文档（BSON/JSON），动态 Schema |
| 存储方式 | 支持多种引擎，需多表关联 | 类 JSON 文档格式，可嵌套存储 |
| 查询语言 | SQL（结构化查询语言） | 类 JavaScript 的查询方式 |
| 扩展性 | 垂直扩展为主，水平扩展较复杂 | 原生支持分片，易于水平扩展 |
| 事务支持 | 完整 ACID 事务 | MongoDB 4.0+ 支持多文档事务 |
| 适用场景 | 结构化数据、强一致性需求 | 灵活 Schema、高并发、海量数据 |



### 2. 什么是 BSON？与 JSON 有什么区别？

**参考答案：**

BSON（Binary JSON）是 MongoDB 使用的二进制编码序列化格式，用于在集合中存储文档和进行数据交换。

BSON 相比 JSON 的扩展包括：
- 支持额外数据类型：Date、Binary Data、ObjectId 等
- 二进制特性优化了存储和检索性能
- 支持更高效的数据遍历（包含长度前缀）

### 3. MongoDB 的 ObjectId 由哪些部分组成？

**参考答案：**

ObjectId 是一个 12 字节的唯一标识符，由以下部分组成：
- 4 字节：时间戳（秒数，Unix 纪元）
- 3 字节：客户端机器 ID
- 2 字节：客户端进程 ID
- 3 字节：自增计数器



### 4. 什么是集合（Collection）和文档（Document）？

**参考答案：**

- **文档（Document）**：MongoDB 中的基本数据单元，类似 JSON 对象，由字段和值组成，支持嵌套文档和数组。
- **集合（Collection）**：一组 MongoDB 文档的集合，相当于关系型数据库中的表。集合是动态 Schema 的，同一集合中的文档可以有不同字段结构。

### 5. MongoDB 支持哪些数据类型？

**参考答案：**

MongoDB 支持丰富的数据类型，包括：
- 基本类型：String、Integer、Double、Boolean、Null
- 复合类型：Object、Array、Binary Data
- 特殊类型：ObjectId、Date、Timestamp、Regular Expression、JavaScript Code
- 地理位置类型：Point、LineString、Polygon 等
- 高级类型：Decimal128（高精度小数）、MinKey/MaxKey


## 二、数据建模

### 6. MongoDB 支持哪两种数据模型？

**参考答案：**

MongoDB 支持两种数据模型：
- **嵌入式数据模型**：将相关数据合并到单个文档结构中，适用于"一起使用、一起存储"的数据。
- **规范化数据模型**：通过引用（reference）从一个文档指向另一个文档，适用于需要独立管理的数据。

选择原则：嵌入式适合"读多写少"且数据量不大的场景；规范化适合数据更新频繁或需要独立访问的场景。

### 7. 在 MongoDB 中设计 Schema 时需要考虑哪些因素？

**参考答案：**

Schema 开发应考虑以下因素：
1. 根据用户需求设计 Schema
2. 如果多个对象常一起使用，将它们合并到单个文档中
3. 如果数据需要独立管理，则通过引用分离
4. 考虑在 Schema 中执行复杂聚合操作的可行性
5. 平衡读性能（嵌入）与写性能（规范化）

### 8. 什么是"反范式化"？在 MongoDB 中为什么要使用它？

**参考答案：**

反范式化是指将本应分散在多个文档/集合中的数据冗余存储到一个文档中。在 MongoDB 中，由于缺乏跨集合的 JOIN 操作（虽然 `$lookup` 提供了类似功能，但性能开销较大），反范式化可以减少查询次数，提升读性能。常见做法包括将子文档直接嵌入父文档，或通过预聚合字段减少实时计算。


## 三、索引

### 9. 什么是 MongoDB 中的索引？有哪些类型？

**参考答案：**

索引是 MongoDB 中用于快速定位数据子集的特殊数据结构，以易于搜索的格式维护数据集合中的部分数据。

常见索引类型包括：
- **单字段索引**：对单个字段建立索引
- **复合索引**：对多个字段建立索引，字段顺序影响查询效率
- **多键索引**：对数组字段建立的索引
- **全文索引**：支持文本搜索
- **地理空间索引**：2dsphere、2d，用于地理位置查询
- **哈希索引**：用于分片键的哈希分布
- **TTL索引**：自动删除过期文档
- **唯一索引**：确保字段值唯一



### 10. 什么是复合索引？字段顺序如何选择？

**参考答案：**

复合索引是对多个字段建立的索引，可以支持涉及多个字段的查询。复合索引字段顺序是性能优化的关键：
- **等值查询字段在前**：将选择性高（唯一值多）的字段放在前面
- **范围查询字段在后**：将用于范围查询（`$gt`、`$lt`）的字段放在复合索引的后面
- **考虑排序需求**：索引字段顺序应尽量与 `sort()` 一致

### 11. 什么是覆盖查询（Covered Query）？如何实现？

**参考答案：**

覆盖查询是指查询的所有字段都在索引中，MongoDB 可以直接从索引返回结果，无需访问磁盘上的文档，从而显著减少 I/O。

实现方式：
- 创建包含查询所需所有字段的索引
- 查询时使用 `projection` 只返回索引中的字段
- 确保 `_id` 字段不在返回字段中（除非 `_id` 也在索引中）

### 12. 如何分析 MongoDB 的查询性能？`explain()` 的关键指标有哪些？

**参考答案：**

使用 `explain("executionStats")` 方法分析查询执行计划：

关键指标：
- `winningPlan.inputStage.stage`：若为 `IXSCAN` 表示使用索引，`COLLSCAN` 表示全表扫描
- `executionStats.executionTimeMillis`：执行耗时
- `executionStats.totalDocsExamined`：扫描的文档数
- `executionStats.totalKeysExamined`：扫描的索引条目数
- `executionStats.nReturned`：实际返回的文档数

优化原则：`totalDocsExamined` 与 `nReturned` 越接近越好。

### 13. 索引有哪些缺点？如何避免过度索引？

**参考答案：**

每创建一个索引都会增加写操作（插入、更新、删除）的开销，并占用额外磁盘空间。过度索引会导致：
- 写性能下降
- 内存占用增加
- 磁盘空间浪费

避免策略：
- 优先为高频查询创建索引
- 定期使用 `$indexStats` 监控索引使用频率，删除未使用的索引
- 删除临时或重复的索引


## 四、聚合框架

### 14. 什么是 MongoDB 的聚合管道（Aggregation Pipeline）？

**参考答案：**

聚合管道是 MongoDB 中用于数据聚合和处理的框架，它将多个操作符连接在一起，形成一个处理管道，每个阶段接收前一个阶段的输出作为输入，执行特定操作后传递给下一个阶段。

### 15. 常用的聚合阶段操作符有哪些？

**参考答案：**

常用聚合阶段操作符包括：
- `$match`：数据筛选，应放在管道早期阶段，可利用索引
- `$group`：数据分组，配合 `$sum`、`$avg`、`$min`、`$max` 等聚合函数
- `$project`：字段投影，用于选择、重命名或计算字段
- `$lookup`：左外连接，从其他集合获取数据（类似 SQL 的 JOIN）
- `$unwind`：将数组字段拆分为多个文档
- `$sort`：排序
- `$limit` / `$skip`：分页
- `$addToSet` / `$push`：数组聚合

### 16. 如何优化聚合管道的性能？

**参考答案：**

优化聚合管道的核心原则：
1. **尽早过滤**：将 `$match` 放在管道最前面，并确保筛选字段有索引
2. **减少数据量**：在 `$group` 之前使用 `$match` 减少处理的数据量
3. **合理使用投影**：用 `$project` 只保留必要字段
4. **注意内存限制**：MongoDB 对聚合操作有 100MB 内存限制，大数据量需启用 `allowDiskUse`
5. **确保管道阶段能被分片集群并行执行**

### 17. 即使 `$lookup` 阶段没有使用索引，为什么整体性能仍可能提升？

**参考答案：**

如果聚合管道的前几个阶段（如 `$match`）使用了索引，这些阶段会快速执行，大幅减少传递给 `$lookup` 阶段的数据量。此外，索引使用可能使数据在内存中更集中，减少磁盘 I/O，并释放更多 CPU 资源给后续阶段。


## 五、复制集与高可用

### 18. 什么是 MongoDB 的复制集（Replica Set）？如何保证高可用？

**参考答案：**

复制集是一组维护同一数据集的 mongod 进程，提供数据冗余和高可靠性。复制集通过以下机制保证高可用：
- **自动故障转移**：Primary 节点故障时，Secondary 节点通过选举自动成为新 Primary
- **数据冗余**：Secondary 节点异步复制 Primary 的数据
- **读写分离**：可将读请求路由到 Secondary 节点分担压力

### 19. 复制集至少需要几个节点？什么是"大多数"原则？

**参考答案：**

复制集最少可以有一个节点（但生产环境无高可用），一般建议至少 3 个节点。选举需要获得 **大多数** 节点的投票支持，定义为 `N/2 + 1`（N 为投票成员数）。节点数为奇数时容错率最高：3 节点可容忍 1 个节点故障，5 节点可容忍 2 个节点故障。

### 20. 什么是仲裁节点（Arbiter）？有什么作用？

**参考答案：**

仲裁节点不存储数据，只参与选举投票，通过心跳包确认集群成员数量。当无法部署奇数个数据节点时（如只有 2 个数据节点），Arbiter 节点可提供所需的最少投票数，避免"脑裂"。但使用 Arbiter 会降低数据冗余和容错能力。

### 21. MongoDB 如何实现数据同步？什么是 Oplog？

**参考答案：**

Secondary 节点通过异步复制 Primary 节点的 **Oplog**（操作日志）来实现数据同步。Oplog 是一个固定大小的 capped collection，记录了所有对数据的修改操作。Secondary 节点持续读取并应用 Oplog 中的操作，保持与 Primary 的数据一致。


## 六、分片集群

### 22. 什么是分片（Sharding）？为什么需要分片？

**参考答案：**

分片是将大型集合的数据分散存储到多个服务器上的过程，是 MongoDB 应对数据增长需求的水平扩展策略。当单台服务器的 CPU、内存、I/O 等无法满足需求时，分片可以有效缓解性能压力。

### 23. MongoDB 分片集群由哪些组件组成？

**参考答案：**

MongoDB 分片集群包含四个核心组件：
- **Shard**：存储实际数据的分片，生产环境每个分片应为复制集
- **Config Server**：存储集群元数据（路由和分片信息），至少 3 个
- **mongos**：应用访问入口，负责请求路由和负载均衡，无状态可任意扩展
- **Replica Set**：为每个 Shard 提供高可用保障

### 24. 什么是分片键（Shard Key）？如何选择？

**参考答案：**

分片键是用于划分数据的字段。选择分片键需考虑：
- **基数高**：字段值分布范围广，避免热点
- **分布均匀**：数据能均匀分散到各分片
- **查询友好**：常用查询条件应包含分片键，避免跨分片查询

分片策略：
- **范围分片**：按值的范围分布
- **哈希分片**：通过哈希函数均匀分布


## 七、事务与ACID

### 25. MongoDB 支持 ACID 事务吗？不同版本的支持情况如何？

**参考答案：**

MongoDB 支持 ACID 事务，但不同版本支持程度不同：
- **3.0 以前**：不支持事务，仅单文档原子性
- **3.0 引入 WiredTiger 引擎**：开始支持单文档事务
- **4.0**：支持复制集部署模式下的多文档事务
- **4.2+**：支持分片集群中的多文档事务
- **7.0+**：引入时序集合等新特性，事务功能更加完善

### 26. MongoDB 如何实现 ACID 四个特性？

**参考答案：**

MongoDB 通过以下机制实现 ACID：
- **原子性**：事务中的所有操作要么全部执行，要么全部回滚
- **一致性**：通过原子性和隔离性确保数据完整性
- **隔离性**：通过 **MVCC** 和 **乐观锁** 实现，默认采用快照隔离
- **持久性**：通过 **Write Concern** 机制，确保数据写入足够多的副本

### 27. MongoDB 事务适合哪些场景？有哪些注意事项？

**参考答案：**

适用于金融交易、电子商务订单处理、库存管理等需要高一致性的场景。注意事项：
- 并非所有场景都需要事务，简单的单文档操作通常足够
- 事务会带来额外性能开销
- 长事务可能影响并发性能
- 需评估业务需求与数据访问模式

## 九、运维与监控

### 30. 什么是 MongoDB 的数据库分析器（Profiler）？如何使用？

**参考答案：**

MongoDB 内置的数据库分析器可显示每个数据库操作的性能信息，用于发现执行时间过长的查询和写操作，帮助判断何时需要创建索引。可通过 `db.setProfilingLevel()` 设置分析级别。

### 31. 如何监控 MongoDB 的慢查询？

**参考答案：**

- 开启慢查询日志：`db.setProfilingLevel(1, { slowms: 100 })`
- 查看 `system.profile` 集合中的记录
- 使用数据库分析器识别慢操作
- 结合 `explain()` 分析慢查询执行计划

### 32. 如果查询优化器没有选择最优索引，如何处理？

**参考答案：**

MongoDB 的查询优化器会自动选择最优计划，但当统计信息不准确或查询复杂度高时，可能选择低效索引。解决方案：
- 使用 `hint()` 方法强制指定索引
- 使用 `planCacheSetFilter` 设置查询计划缓存索引过滤器
- 定期更新统计信息（`db.collection.stats()` 可查看）


## 十、原理深挖

### 33. MongoDB 的存储引擎有哪些？WiredTiger 的特点是什么？

**参考答案：**

MongoDB 主要存储引擎包括：
- **MMAPv1**：早期版本，已废弃
- **WiredTiger**：当前默认存储引擎，从 MongoDB 3.0 开始引入

WiredTiger 的核心特点：
- 文档级并发控制
- 支持压缩（snappy、zstd）
- 支持事务
- 高性能读写
- 内存高效利用



### 34. MongoDB 如何实现 MVCC？

**参考答案：**

MongoDB 使用 WiredTiger 存储引擎的 MVCC 机制实现事务隔离。每个事务开始时都会构造一个快照，通过 `snap_min` 和 `snap_max` 两个属性确定事务可见的数据范围。事务执行期间看到的是该快照，其他事务的修改在提交前不可见。

### 35. 什么是 Write Concern？如何配置？

**参考答案：**

Write Concern 控制 MongoDB 确认写操作完成的程度，影响数据的持久性和可靠性：
- `w: 0`：不确认，性能最高但可能丢失数据
- `w: 1`：确认 Primary 写入（默认）
- `w: "majority"`：确认大多数节点已写入
- `j: true`：要求写入日志（Journal）后才确认
- `wtimeout`：指定超时时间


## 十一、面试实战：高频手写题

### 36. 创建一个名为 `users` 的集合，插入用户文档，并为 `email` 字段创建唯一索引。

```javascript
// 创建集合（隐式，插入文档时自动创建）
// 插入文档
db.users.insertOne({ name: "张三", email: "zhangsan@example.com", age: 25 })
db.users.insertMany([
  { name: "李四", email: "lisi@example.com", age: 30 },
  { name: "王五", email: "wangwu@example.com", age: 28 }
])

// 创建唯一索引
db.users.createIndex({ email: 1 }, { unique: true })
```

### 37. 查询 `users` 集合中年龄大于 25 岁的用户，只返回 `name` 和 `email` 字段。

```javascript
db.users.find(
  { age: { $gt: 25 } },
  { name: 1, email: 1, _id: 0 }
)
```

### 38. 使用聚合管道统计每个年龄段的用户数量。

```javascript
db.users.aggregate([
  { $group: { _id: "$age", count: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])
```

### 39. 更新 `users` 集合中 `name` 为 "张三" 的文档，将年龄增加 1。

```javascript
db.users.updateOne(
  { name: "张三" },
  { $inc: { age: 1 } }
)
```

### 40. 删除 `users` 集合中年龄大于 50 岁的用户。

```javascript
db.users.deleteMany({ age: { $gt: 50 } })
```

### 41. 查询 `users` 集合中前 10 条数据，按年龄降序排列。

```javascript
db.users.find().sort({ age: -1 }).limit(10)
```

### 42. 在分片集群中为一个集合启用分片功能。

```javascript
// 首先在数据库上启用分片
sh.enableSharding("myDatabase")

// 为集合指定分片键（哈希分片示例）
sh.shardCollection("myDatabase.users", { userId: "hashed" })
```


## 十二、总结

### 43. MongoDB 相比其他 NoSQL 数据库（如 Redis、Cassandra）的核心优势是什么？

**参考答案：**

- **功能最丰富**：支持复杂查询、索引、聚合、事务等，最像关系型数据库
- **Schema 灵活**：动态 Schema 适应快速迭代的业务需求
- **原生高可用与扩展性**：内置复制集和分片机制
- **丰富的查询语言**：类 JavaScript 语法，功能强大
- **良好的生态系统**：支持 C、C++、Java、Python、Node.js、Go、Ruby 等多种语言
- **时序数据支持**：MongoDB 7.0 原生时序数据库，高效处理 IoT 数据

### 44. MongoDB 有哪些局限性？

**参考答案：**

- 存储空间相比关系型数据库较大
- 复杂多表关联（JOIN）性能较弱（虽然 `$lookup` 支持，但不推荐频繁使用）
- 运维工具成熟度不如传统商业数据库
- 对于严格的结构化数据场景，关系型数据库可能更合适
- 事务在分布式场景下性能开销较大

# H2 数据库

## 一、基础概念与使用场景

### 1. 什么是 H2 数据库？它的主要特点是什么？

**参考答案：**

H2 是一个用 Java 编写的开源关系型数据库，主打**轻量级、嵌入式、高性能**。主要特点包括：

- 纯 Java 实现，无需安装，一个 JAR 文件即可运行。
- 支持嵌入模式（与应用程序同 JVM 运行）和服务器模式（C/S 架构）。
- 支持内存表（`jdbc:h2:mem:test`）和持久化文件存储。
- 提供基于浏览器的 Web 控制台（`/h2-console`）。
- 支持多种数据库的兼容模式（MySQL、PostgreSQL、Oracle、SQL Server 等），便于迁移。
- 支持完整的 SQL 标准、事务（含 MVCC）、索引、存储过程等。
- 体积小巧（约 2MB），启动快，常用于单元测试、原型开发、本地缓存。

### 2. H2 主要用在哪些场景？为什么不适合生产环境的大规模应用？

**参考答案：**

**适用场景：**

- **单元测试/集成测试**：内存模式 + 自动创建/销毁表，测试之间隔离。
- **本地开发环境**：快速启动，无需安装外部数据库。
- **嵌入式应用**：桌面软件、移动端（通过 Java 或 Kotlin）、IoT 设备。
- **小型演示或原型系统**：无需运维，数据持久化简单。

**不适合生产大规规模应用的原因：**

- 并发性能相对有限（基于文件锁或内存，非分布式）。
- 缺乏主从复制、集群、高可用等企业级特性。
- 对于海量数据（GB 以上）和复杂查询的优化不足。
- 没有商业支持或丰富的运维工具。

> 但某些小型生产系统（如轻量级后台、单机工具）也在使用 H2，需自行评估。

## 二、连接与运行模式

### 3. H2 支持哪几种运行模式？如何连接？

**参考答案：**

| 模式 | 说明 | JDBC URL 示例 |
|------|------|----------------|
| **嵌入式** | 与应用程序同 JVM，数据通过本地文件或内存存储，应用停止则数据库关闭 | `jdbc:h2:file:~/mydb`（文件持久化）<br>`jdbc:h2:mem:test`（内存） |
| **服务器模式** | 独立进程启动 H2 服务器（TCP），多个客户端通过网络连接 | `jdbc:h2:tcp://localhost:9092/~/mydb` |
| **混合模式** | 同时支持嵌入式本地连接和远程 TCP 连接，需要同时启动服务器 | `jdbc:h2:~/mydb;AUTO_SERVER=TRUE` |

- 常用连接参数：`DB_CLOSE_DELAY=-1`（保持数据库打开直至 JVM 退出）、`MODE=MySQL`（兼容模式）。

### 4. H2 的内存模式（mem）和数据持久化模式（file）有什么区别？

**参考答案：**

| 特性 | 内存模式 | 文件模式 |
|------|----------|----------|
| 数据存储 | 完全在 JVM 堆内存中，退出即丢失 | 写入本地文件（.mv.db） |
| 性能 | 极高（无磁盘 IO） | 中等，受磁盘影响 |
| 数据持久化 | 不持久化，每次启动为空 | 重启后数据恢复 |
| 典型场景 | 单元测试、临时计算 | 开发环境、小型生产、需要保留数据 |
| 多连接 | 默认仅当前 JVM 内可访问；若开启 `DB_CLOSE_DELAY=-1` 可跨连接 | 允许多个连接（需配置） |

- 内存模式示例：`jdbc:h2:mem:test;DB_CLOSE_DELAY=-1`（保持数据直到 JVM 结束）。
- 注意：内存模式的数据**不会**被多个进程共享。

## 三、兼容模式与 SQL 方言

### 5. H2 如何兼容其他数据库（如 MySQL、PostgreSQL）？有什么限制？

**参考答案：**

- 通过在 JDBC URL 中添加 `MODE` 参数：`jdbc:h2:mem:test;MODE=MySQL`
- 兼容模式会调整：
  - 函数别名（如 `LIMIT`、`NOW()`、`LAST_INSERT_ID()` 等）。
  - 数据类型映射（如 `TINYINT`、`ENUM`）。
  - 标识符引号（MySQL 的反引号 vs H2 的双引号）。
  - 空值排序行为、自增列语法等。
- **限制**：
  - 不是 100% 兼容，某些专有 SQL 语法可能不支持（如 `REPLACE INTO`、`ON DUPLICATE KEY UPDATE` 需改写）。
  - 存储过程、触发器的方言差异较大。
  - 事务隔离级别行为可能略有不同。
- 建议：使用 H2 测试时，尽量使用通用 SQL，避免深度依赖特定数据库方言。

### 6. 在 H2 中如何模拟 MySQL 的 `LAST_INSERT_ID()`？

**参考答案：**

- 使用 `MODE=MySQL` 后，H2 内置了 `LAST_INSERT_ID()` 函数，行为与 MySQL 类似。
- 或者使用标准 SQL：`CALL IDENTITY()` 或 `SCOPE_IDENTITY()`。
- 示例：
  ```sql
  INSERT INTO users (name) VALUES ('Alice');
  SELECT LAST_INSERT_ID();  -- 返回生成的主键
  ```

## 四、事务与并发

### 7. H2 支持事务吗？默认隔离级别是什么？

**参考答案：**

- 支持完整的事务（BEGIN/COMMIT/ROLLBACK）。
- 默认隔离级别：**READ COMMITTED**。
- 支持的隔离级别：
  - `READ UNCOMMITTED`
  - `READ COMMITTED`（默认）
  - `REPEATABLE READ`
  - `SERIALIZABLE`
- 通过 `SET TRANSACTION ISOLATION LEVEL` 修改。

### 8. H2 是否支持 MVCC？如何处理并发？

**参考答案：**

- H2 支持**多版本并发控制（MVCC）**（从较新版本开始，如 1.4.197+ 默认启用）。
- 实现方式：使用行级锁 + 事务快照，读写不互斥。
- 启用 MVCC 时，`SELECT` 不会阻塞 `UPDATE`，反之亦然。
- 旧版本可能使用表级锁，建议使用较新版本并确认 `MVCC=TRUE`（默认）。
- 并发性能：对于嵌入式单进程访问足够；多进程/远程模式性能有限。

## 五、与 Spring Boot 集成

### 9. 如何在 Spring Boot 中配置 H2 数据库（用于测试或开发）？

**参考答案：**

- 添加依赖（`pom.xml`）：
  ```xml
  <dependency>
      <groupId>com.h2database</groupId>
      <artifactId>h2</artifactId>
      <scope>runtime</scope>
  </dependency>
  <!-- 可选：Web 控制台 -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
  </dependency>
  ```

- `application.properties` 配置示例（内存模式）：
  ```properties
  spring.datasource.url=jdbc:h2:mem:testdb
  spring.datasource.driverClassName=org.h2.Driver
  spring.datasource.username=sa
  spring.datasource.password=
  spring.h2.console.enabled=true
  spring.h2.console.path=/h2-console
  spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
  ```

- 启动应用后，访问 `http://localhost:8080/h2-console` 可查看数据。

### 10. 在 Spring Boot 测试中，如何保证每个测试用例独立的数据环境？

**参考答案：**

- 使用 H2 内存模式，并在测试配置中设置 `spring.datasource.url=jdbc:h2:mem:test;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`。
- 配合 `@Transactional` + `@Rollback`，每个测试方法自动回滚。
- 或者使用 `@Sql` 注解在每个测试前执行初始化脚本。
- Spring Boot 测试默认会为每个测试类创建一个独立的数据库连接，但表结构可能共享。通常最佳实践：
  ```java
  @DataJpaTest
  @AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.ANY)
  // 默认会使用 H2 内存库，自动创建表
  ```

## 六、高级特性与注意事项

### 11. H2 支持全文搜索吗？

**参考答案：**

- 支持原生全文搜索（基于 Lucene 或内部实现），但功能有限。
- 启用方式：`CREATE ALIAS FT_SEARCH ...` 或使用 `SELECT * FROM FT_SEARCH('keyword', 0, 0)`。
- 更推荐在生产数据库（如 PostgreSQL 或 Elasticsearch）中做全文搜索，H2 仅用于测试。

### 12. H2 是否支持存储过程、函数和触发器？

**参考答案：**

- 支持 Java 编写的存储过程和函数（通过 `CREATE ALIAS` 关联 Java 静态方法）。
- 支持 SQL 编写的函数和触发器（`CREATE TRIGGER`）。
- 示例：
  ```sql
  CREATE ALIAS HELLO AS 'String hello() { return "Hello"; }';
  SELECT HELLO();
  ```
- 对于复杂业务逻辑，建议放在应用层而非数据库。

### 13. H2 数据库文件（.mv.db）损坏如何修复？

**参考答案：**

- 首先尝试使用 H2 自带的恢复工具：`java -cp h2*.jar org.h2.tools.Recover`，会生成 SQL 恢复脚本。
- 或者使用 `RECOVER` 命令：
  ```sql
  RECOVER FROM 'path/to/mydb.mv.db';
  ```
- 也可以将损坏的数据库文件挂载到新的 H2 实例，执行 `CHECKPOINT` 或 `SHUTDOWN COMPACT`。
- 重要数据建议定期备份（H2 支持在线备份：`BACKUP TO 'backup.zip'`）。

### 14. H2 的连接池推荐使用什么？如何监控连接状态？

**参考答案：**

- H2 本身是轻量级，通常配合 HikariCP（Spring Boot 默认）或 Tomcat JDBC Pool。
- 连接 URL 中可以启用统计信息：`;TRACE_LEVEL_FILE=2;TRACE_LEVEL_SYSTEM_OUT=1`。
- 监控连接：执行 `SHOW SESSIONS` 查看当前连接和事务。

## 七、常见陷阱与实战问题

### 15. 为什么 H2 控制台看不到最近插入的数据？

**参考答案：**

- 原因：内存模式下，如果 URL 中没加 `DB_CLOSE_DELAY=-1`，数据可能随着连接关闭而被清除。
- 解决：确保连接 URL 包含 `;DB_CLOSE_DELAY=-1`。
- 另一种情况：使用了不同的事务隔离级别或未提交事务。

### 16. H2 与 HSQLDB 有什么区别？如何选择？

**参考答案：**

| 特性 | H2 | HSQLDB |
|------|----|--------|
| 作者 | Thomas Mueller（前 HSQLDB 开发者） | The HSQLDB Development Group |
| 历史 | 从 HSQLDB 分支，完全重写 | 更老的项目 |
| 性能 | 一般更快（特别是内存模式） | 较慢，但稳定 |
| 功能 | 更现代（MVCC、兼容模式更丰富） | 较保守 |
| 社区活跃度 | 高（持续更新） | 中等 |
| 嵌入式常用度 | 更流行（Spring Boot 默认） | 较冷门 |

**选择建议**：新项目优先选 H2，尤其是 Spring Boot 生态；老项目或已有 HSQLDB 依赖可继续使用。

### 17. 如何用 H2 测试 MySQL 特有的 SQL 语法（如 `REPLACE INTO`）？

**参考答案：**

- 启用 MySQL 兼容模式：`jdbc:h2:mem:test;MODE=MySQL`
- H2 会支持 `REPLACE INTO` 语法，但行为可能与 MySQL 不完全一致（例如主键冲突时删除再插入）。
- 若仍不支持，可改写为 `MERGE INTO` 语法：
  ```sql
  MERGE INTO users (id, name) KEY(id) VALUES (1, 'Alice');
  ```

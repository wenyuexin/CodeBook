# Nacos 

### 1\. Nacos 的命名来源于什么？它的两个核心角色分别是什么？

**参考答案**： Nacos 全称是 **Dynamic Naming and Configuration Service**，其中 “Naming” 指服务命名（服务发现），“Configuration” 指配置管理。它的两个核心角色：

- **注册中心**：管理微服务的实例注册与发现。

- **配置中心**：管理应用的动态配置，支持热更新。

---

### 2\. Nacos 如何实现服务实例的自动注册和下线？请描述客户端和服务端的交互过程。

**参考答案**：

- **注册**：客户端启动时，通过 Nacos Client SDK 向服务端发送 HTTP/gRPC 请求，携带服务名、IP、端口、权重、元数据。服务端将实例存入内存和持久化存储（如 MySQL）。

- **心跳**：客户端定期（默认5秒）发送心跳到服务端，服务端记录最后心跳时间。

- **下线**：

  - 正常下线：客户端主动发送注销请求。

  - 异常下线：服务端连续15秒未收到心跳标记为不健康；30秒未收到则剔除。

- **主动探测**（可选）：服务端可主动探测客户端健康端点（如 HTTP `/health`）。

---

### 3\. Nacos 的临时实例和持久化实例有什么区别？分别适用于什么场景？

**参考答案**：

|特性|临时实例|持久化实例|
|-|-|-|
|**存储方式**|仅内存存储，不落盘|存储到数据库（如 MySQL）|
|**健康检查**|客户端心跳，超时剔除|服务端主动探测，不主动剔除|
|**生命周期**|跟随客户端，无心跳则自动删除|手动删除或长期保留|
|**适用场景**|普通微服务（弹性伸缩、频繁上下线）|网关、数据库代理、常驻服务|

**场景举例**：

- 临时实例：业务微服务（订单、用户等），实例数动态变化。

- 持久化实例：数据库代理、消息队列 broker，即使暂时不可用也需要保留元数据。

---

### 4\. Nacos 配置中心如何实现配置的版本管理和回滚？

**参考答案**：

- **版本管理**：每次修改配置时，Nacos 会保存一个历史版本，记录配置内容、MD5、修改时间、修改人。

- **回滚**：在控制台选择某个历史版本，点击“回滚”，系统会将当前配置覆盖为所选版本的内容，并产生一条新的修改记录。

- **API 支持**：可通过 `/nacos/v1/cs/history` 接口查询版本列表和回滚。

---

### 5\. Nacos 如何支持多环境、多租户的配置隔离？

**参考答案**： 通过 **Namespace** 实现隔离：

- 为不同环境（dev/test/prod）或不同租户创建独立的 Namespace。

- 每个 Namespace 拥有独立的服务和配置。

- 客户端配置时指定 `spring.cloud.nacos.config.namespace=xxx` 即可。

- 不同 Namespace 之间数据完全不互通，适合多团队、多环境共享同一套 Nacos 集群。

### 6\. 请解释 Nacos 的 Distro 协议和 Raft 协议分别用在什么场景？

**参考答案**：

- **Distro 协议**：Nacos 自研的 AP 协议，用于服务注册中的临时实例数据同步。采用去中心化、最终一致性，每个节点负责一部分服务实例的写操作，通过异步复制达到一致。适合高可用、对一致性要求不高的服务发现场景。

- **Raft 协议**：用于 CP 场景，包括：

  - 持久化实例的元数据存储

  - 配置中心的数据一致性

  - 集群内节点的 leader 选举 保证强一致性，适合配置数据、持久化服务元数据。

### 7\. 在 Spring Cloud 项目中，如何让 Nacos 配置动态刷新生效？有哪些注意事项？

**参考答案**：

- 在需要动态刷新配置的类上标注 `@RefreshScope`。

- 配置变更后，Spring Cloud Context 会销毁原 Bean 并重新创建，从而使用新配置。

- **注意事项**：

  - `@RefreshScope` 会导致 Bean 代理，性能略有损耗，不应滥用。

  - 静态字段无法自动刷新，需改为非静态或通过 `@ConfigurationProperties` 配合 `@RefreshScope`。

  - 某些配置（如数据库连接池参数）刷新后需要重新初始化连接池，可能需要额外监听 `RefreshEvent` 并手动处理。

### 8\. Nacos 客户端是如何缓存服务实例列表的？当 Nacos Server 全部宕机时，客户端还能正常调用吗？

**参考答案**：

- **缓存机制**：客户端首次拉取服务实例列表后，会缓存在本地内存（和磁盘备份）。同时注册监听器，当服务端推送变更时更新缓存。

- **服务端宕机时**：客户端无法拉取最新实例，但仍可使用本地缓存中的实例列表继续发起调用。只要缓存中的实例健康，服务依然可用。但无法感知新实例上线或旧实例下线，可能导致部分调用失败。因此生产环境需要部署 Nacos 集群，避免单点故障。

### 9\. Nacos 与 Kubernetes 的服务发现有何不同？两者如何协同？

**参考答案**：

|维度|Nacos|Kubernetes (CoreDNS + Service)|
|-|-|-|
|注册方式|主动注册（客户端调用 API）|自动注册（Pod 创建时通过 Endpoints 注入）|
|健康检查|心跳 + 主动探测|就绪探针 + 存活探针|
|服务粒度|业务服务（如订单服务）|Pod IP + 端口，Service 抽象|
|配置中心|内置|ConfigMap + Secret|
|负载均衡|客户端负载均衡（Ribbon等）|服务端负载均衡（kube-proxy）|

**协同方式**：

- 将 Nacos 部署在 K8s 上，使用 StatefulSet 保证稳定网络标识。

- 微服务通过 Nacos 进行服务发现和配置管理，同时使用 K8s 做容器编排和资源管理。

- 可通过 **Spring Cloud Kubernetes** 或 **Nacos-Sync** 将 K8s Service 同步到 Nacos，实现混合注册中心。

### 10\. 你如何监控和告警 Nacos 集群的健康状态？列举关键指标。

**参考答案**：

关键监控指标：

- **节点健康**：每个节点的 JVM 内存、GC 次数、CPU、磁盘使用率。

- **服务数量**：已注册的服务总数、临时/持久实例数。

- **心跳成功率**：心跳请求总数、失败数、超时数。

- **配置变更次数**：配置写入 QPS、长轮询挂起数量。

- **Raft 状态**：Leader 是否稳定、任期变化次数、日志复制延迟。

**常用工具**：

- Nacos 自带的 `/nacos/v1/ns/operator/metrics` 端点（Prometheus 格式）。

- 集成 Prometheus + Grafana 展示仪表盘。

- 设置告警规则：如“某服务实例数骤降 50%”、“心跳超时比例 > 10%”、“Nacos 节点宕机”。
